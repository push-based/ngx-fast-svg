## At a glance

| Library            | SSR        | Lazy loading       | Optimized render performance |
| ------------------ | ---------- | ------------------ | ---------------------------- |
| `ngx-fast-svg`     | easy       | browser native     | ✔️                           |
| `font-awesome`     | hard       | ❌                 | ❌                           |
| `ant`              | moderate   | ❌                 | ❌                           |
| `material`         | easy       | ❌                 | ❌                           |
| `angular-svg-icon` | moderate   | ❌                 | ❌                           |
| `ionic`            | moderate   | ❌                 | ✔️                           |

**SSR.** All six can render on the server. The rating is about how much setup it takes: `easy` means a provider or a module, `moderate` means a custom loader or extra configuration, `hard` means working around the library.

**Lazy loading.** Loading an icon's file only when the icon is near the viewport. `ngx-fast-svg` delegates this to the browser's `loading="lazy"` image logic; the others fetch when the component is created.

**Optimized render performance.** Whether rendering many instances stays cheap: one shared DOM node per icon, `contain` and `content-visibility` hints, and no per-instance parsing.

## Bundle cost

{{bundle-stats}}

**How this is measured.** Attributing chunks inside one large application gives numbers that say more about that application than about the libraries, so each row comes from its own build instead. `tools/bundle-stats` holds seven minimal Angular applications: a baseline that uses no icon library, and one per library that renders the same 21 icons the way that library intends. They all bootstrap the same providers — the router and an `HttpClient`, which almost every application already ships — and they are all built with identical production settings. A library's cost is its build minus the baseline build, so shared machinery is never billed to anyone.

**Added.** JavaScript the browser must download and parse before the application starts, over the baseline. Gzipped is the number that matters over the wire; raw is what the parser has to chew through.

**Icons.** Whether the icon artwork rides along in the JavaScript bundle or is fetched as `.svg` files at runtime. `font-awesome` and `ant` have no file-based mode, so their rows include 21 icon definitions. The other four pay nothing per icon in JavaScript, which is why their cost stays flat as an icon set grows — a library that bundles icons gets steadily more expensive, one that fetches them does not.

**Loaded on demand.** JavaScript the build emits but does not load at startup. Only `ionic` has any: it registers its icons as lazy-loaded web components, so part of its cost arrives after boot rather than before it.

Each row is the smallest working setup for that library's icon and nothing else. The `ionic` row in particular leaves out `provideIonicAngular()`, which configures Ionic's platform and overlays rather than its icon — including it would have charged the icon 135 KB of unrelated framework.

The numbers are regenerated by `npm run bundle-stats` and checked on every pull request, so they cannot drift away from the code they describe.

## Try it yourself

The [library comparison demo](demo/compare) renders the same 21 icons with each library. Pick a library, open the Performance panel of your browser's devtools, start recording and press **Add** to render another batch. The **Off screen** layout pushes every icon below the fold, which is where lazy loading and `content-visibility` make the difference; **Distributed** spreads them so only some are visible.

Each page keeps the same URL shape, `/demo/compare/<library>/<layout>/<count>`, so you can reload a scenario or compare two libraries side by side in two tabs.
